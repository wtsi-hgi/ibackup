- [x] The test suite is too slow. `make test` takes about 47 minutes for the

  - Source: PR #193, mjkw31, comment 4183397023: "That's absurd; how is the

  - Known factors: creating an iRODS collection takes about 4.6s on the test
    zone, and each Convey leaf creates its own collection; the main package

  - Red: main package 46:21 under `make test` and 47:24 under `make race`
    (deps 9e97e15: 2896s / 2872s); TestRemove 1052s, TestTrashRemove 824s,
    TestEdit 411s, TestPuts 236s were 90% of it. Collection creation is

    `irods.go`), `main_test.go` and `Makefile`: a lazily started background
    pool of pre-created unique collections; a test's collections removed 8

- [x] Test servers can collide on ports when main-package tests run as
  parallel processes: ports are picked with freeport and bound later, and
  `waitForServer` uses InsecureSkipVerify and ignores a failed `Start`, so a
  different process's server can answer (seen once: `tls: failed to verify
  certificate ... localhost:35787` in `impersonateUser` Login). Possible fix:
  `waitForServer` trusts only `s.cert`, checks `s.srvErr`, and retries on a
  new port.
  - Source: found while speeding up the tests (this branch), 2026-10-06.
  - Fixed in `internal/testutil/tlsserver.go` and `main_test.go`: the
    in-process server starts via `StartTLSServer`, which accepts only a
    server presenting the test server's own cert, detects a failed start, and
    retries on a new port on EADDRINUSE (not when the URL is already fixed);
    external servers use `WaitForTLSServer`. Tested without iRODS (a foreign
    TLS server on the port); mutants dropping the cert check, the start-error
    check or the retry fail. No collisions in the full parallel runs.
  - Amended after PR #194 review (see the `tlsserver` items below): the
    retry machinery and `internal/testutil/tlsserver.go` were replaced by a
    certificate-checked wait in `main_test.go`. `waitForServer` trusts only
    `s.cert` and stops early when `s.srvErr` reports a failed start, so a
    collision fails promptly and clearly instead of reaching another
    process's server; it no longer retries on a new port.
